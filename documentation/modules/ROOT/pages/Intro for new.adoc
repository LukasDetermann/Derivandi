== Overview

Every program talks about something.
A webshop will talk about products, customers, orders, and payments.
Programs can also talk about other programs in the same way (metaprogramming).
The lifecycle from writing code to its execution is long, and there are many different opportunities for metaprogramming.
Each has different tradeoffs depending on the context.

The code written with this library runs in the Java compiler.
It takes in source files and outputs class files.
Derivandi can do two things:

. code generation
. validation


== Annotations

Writing `CustomerEntity` or `@Entity Customer` represents the same information.
The structured way of expressing metadata as annotations is just easier for tools to process.
Annotations don't do anything on their own.

The most relevant properties of annotations for compile-time metaprogramming are:

. `@Retention` configures how long an annotation should be kept:
.. `SOURCE` available in source code during compilation, but not included in the compiled class file
.. `CLASS` (Default) included in the compiled class file, but not available at runtime
.. `RUNTIME` always present
. `@Target` configures where an annotation can be used
. `@Inherited` configures whether a class can  inherit an annotation from its superclass

== Derivandi

The core features are

=== Code Model

It is possible to query the code model from modules down to method parameters.

[%linenums,java]
----
D.Class string = context.getClassOrThrow("java.lang.String");
for (D.Property property : string.getProperties()) {
   D.Method getter = property.getGetter();
   for (D.Parameter parameter : getter.getParameters()) {
      System.out.println(parameter.isFinal());
   }
}
----

=== JavaDsl

The JavaDsl makes it easy to generate source files.
The Code Model can be used with the JavaDsl.
Modules down to method parameters are type-safe.
Everything has a flexible String overload.

[%linenums,java]
----
JavaDsl.class_().package_("org.example")
             .public_().name("MyClass")
             .field(JavaDsl.field().private_().type("String").name("foo"))
             .method(JavaDsl.method().public_().resultType("void").name("bar"))
             .renderDeclaration(RenderingContext.createRenderingContext());
----

=== File Generation

There are three kinds of files that can be generated.
class files, resource files, and source files.
Generated source files will be compiled like any other.
Generating them should be preferred over generating class files.
The JavaDsl can be used.


[%linenums,java]
----
context.writeClassFile();
context.writeResource();
context.writeAndCompileSourceFile(JavaDsl.class_().package_("org.example")
                                         .public_().name("MyClass")
                                         .constructor(JavaDsl.constructor().surroundingType()));
----

=== Logging

Logging can be done on three levels: error, warning, or info.
Errors will interrupt the compilation at the end of the current round.
It is possible to log with a reference to a specific place in the code.

[%linenums,java]
----
context.logAndRaiseError("broken");

D.Class string = context.getClassOrThrow("java.lang.String");
context.logWarningAt(string, "let me warn you about Strings!");

context.logInfo("i was here");
----

== Compiler

=== Overview

Derivandi runs in the compiler.
Compilation happens in five steps.

. *Parse* +
The source files are parsed
. *Enter* +
The parser result is entered into the internal data structures
. *Annotation Processing* +
All annotation processors, like Derivandi, are executed.
This may produce new source files.
If new source files are generated, steps 1-3 will be run again for just these.
. *Analyse* +
The code is analyzed and validated
+
TIP: This means that "normal" code can reference code that will only be generated at compile time.
. *Generate* +
Class files are generated


=== Compilation Units

Derivandi code is normal Java code that gets executed at compile time.
Therefore, it needs to be compiled already.
This makes multiple compilation units necessary, meaning multiple Maven modules or equivalent in other build tools.
